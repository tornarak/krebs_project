     MCP Parity — Shared State with the GUI

     Context

     The LLM is a collaborator working alongside the GUI user. Both share the
     same Neoplasm.Scanner state: scan results, watches, attachment status. The
     MCP should give the LLM full read/write access to this shared state so it
     can see what the user sees, add watches, label them, generate schemas, etc.

     Since all state lives in Elixir GenServers (not in the NIF/GUI), MCP tools
     are just function calls to the same APIs the GUI events trigger.

     ---
     Architecture

     Where the tools live

     The new tools call Neoplasm.Scanner and Neoplasm.SchemaGen — modules in the
      neoplasm app. krebs can't have a compile-time dependency on neoplasm
     (dependency flows the other direction).

     Solution: app-config tool extension.

     krebs's tools/0 already returns a hardcoded list. Add one line to pull
     extras from config:

     # krebs/lib/krebs/server.ex
     def tools do
       base = [ ... existing 23 tools ... ]
       extra = Application.get_env(:krebs, :extra_mcp_tools, [])
       base ++ extra
     end

     neoplasm registers its tools at config time:

     # neoplasm/config/config.exs
     config :krebs, :extra_mcp_tools, [
       Neoplasm.MCP.ListWatches,
       Neoplasm.MCP.AddWatch,
       Neoplasm.MCP.RemoveWatch,
       Neoplasm.MCP.UpdateWatch,
       Neoplasm.MCP.ListResults,
       Neoplasm.MCP.GenerateSchema,
       Neoplasm.MCP.LoadSchema,
     ]

     This way krebs stays clean — no neoplasm references — and the tools only
     exist when neoplasm is in the dependency tree.

     But: Bandit starts in Krebs.Application.start/2 which runs before
     Neoplasm.Application. Application.get_env reads compile-time config, which
     is available before any app starts. So the tool modules must already be
     compiled — which they are, since neoplasm depends on krebs (krebs compiles
     first, but the config is set by neoplasm's config.exs which Mix merges
     before compilation). This works.

     New public API on Neoplasm.Scanner

     Currently watches and results don't have read-only public accessors. Add:

     # neoplasm/lib/neoplasm/scanner.ex
     def list_watches, do: GenServer.call(__MODULE__, :list_watches)
     def list_results, do: GenServer.call(__MODULE__, :list_results)

     With corresponding handle_call clauses that return the state.

     Move SchemaGen to krebs

     Neoplasm.SchemaGen has zero neoplasm deps in its core logic (validate,
     generate, save). Only load/1 calls Neoplasm.Nif.set_schemas/1.

     Move to Krebs.SchemaGen:
     - validate/2, generate/3, save/2 — unchanged
     - load/1 — compile + register only, no NIF call

     Neoplasm.Window's handler adds the GUI refresh after calling
     Krebs.SchemaGen.load/1:
     case Krebs.SchemaGen.load(code) do
       {:ok, msg} ->
         Nif.set_schemas(build_schema_list())
         Nif.set_schema_load_result(msg)
       ...
     end

     Delete neoplasm/lib/neoplasm/schema_gen.ex.

     ---
     Tool Specifications

     list_watches

     name: "list_watches"
     params: {} (none)
     returns: JSON array of {addr, label, type, auto_refresh, bare_map,
     value_or_error}
     Calls Neoplasm.Scanner.list_watches/0.

     add_watch

     name: "add_watch"
     params:
       addr: string (required) — hex address
       type: string (required) — Rekto type expression, e.g. ":u32", ":f32",
     "{:string_buffer, 32}"
     returns: "ok" or error
     Calls Neoplasm.Scanner.add_watch/2 (currently a cast — change to call for
     the MCP path, or keep cast + return ack).

     remove_watch

     name: "remove_watch"
     params:
       addr: string (required) — hex address
     returns: "ok"
     Calls Neoplasm.Scanner.remove_watch/1.

     update_watch

     name: "update_watch"
     params:
       addr: string (required) — hex address
       label: string (optional) — display label
       auto_refresh: boolean (optional) — default true
       bare_map: boolean (optional) — strip __meta__
     returns: "ok"
     Calls Neoplasm.Scanner.update_watch_info/4.

     list_results

     name: "list_results"
     params: {} (none)
     returns: JSON array of hex address strings from the current scan set
     Calls Neoplasm.Scanner.list_results/0 → reads :neoplasm_scan_set results.

     generate_schema

     name: "generate_schema"
     params:
       module_name: string (required) — e.g. "MyGame.Player"
       fields: array of objects (required) — each:
         name: string — field name
         type: string — e.g. "u32", "f32", "[string_buffer; 32]"
         offset: integer — byte offset
         size: integer — byte size
         constraints: string (optional)
     returns: generated Elixir source code string
     Calls Krebs.SchemaGen.generate/3.

     load_schema

     name: "load_schema"
     params:
       code: string (required) — Elixir source code
     returns: success message with module name, or error
     Calls Krebs.SchemaGen.load/1. If Neoplasm.Nif is loaded, also refreshes the
      GUI schema list.

     ---
     Verification

     1. cd krebs && mix compile — new SchemaGen module, updated tools/0
     2. cd neoplasm && mix compile — new MCP tools, updated scanner/window
     3. Start: iex -S mix
     4. MCP tool: list_watches → empty array
     5. GUI: attach to process, navigate hex dump, watch an address
     6. MCP tool: list_watches → see the watch with addr, type, value
     7. MCP tool: add_watch {addr: "0x...", type: ":u32"} → GUI shows new watch
     8. MCP tool: update_watch {addr: "0x...", label: "health"} → GUI shows
     label
     9. MCP tool: remove_watch → GUI watch disappears
     10. MCP tool: list_results after a GUI scan → shows addresses
     11. MCP tool: generate_schema → returns valid .exs source
     12. MCP tool: load_schema with generated code → list_schemas shows new
     module
